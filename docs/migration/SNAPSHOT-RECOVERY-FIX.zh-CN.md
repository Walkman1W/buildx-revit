# 快照事件恢复边界

快照事件连续性失效后，status 返回明确错误，要求显式执行 `action=start` 重建完整基线；旧 token 不再有效。恢复使用故障代数，重建期间出现的新故障不会被本次重建消除。其他文档的无法识别事件仍保守地使连续性失效。

完整枚举使用 1000ms、单次事件处理使用 150ms 的协作式时间预算，超限失效关闭。这些检查不能强制中断正在阻塞的单次 Revit API 调用；大项目也可能因此保守地无法建立或维持基线。这些数值不是实际 Revit 性能保证。

已发布的读取请求如遇源文档漂移，失败证据保留原请求 ID 与原回执 owner，状态为 unconfirmed；只核查原回执，不重发。

隔离受控检查：C# owner peers 46/46、bridge peers 23/23，Node 相关回归 86/86；Revit 2024 API 引用编译成功。尚未在真实 Revit、实际模型或真实 UI 验证事件行为、响应时间和恢复体验。
