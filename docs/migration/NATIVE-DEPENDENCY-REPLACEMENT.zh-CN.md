# BuildX 原生查询标注与系统图替代规划

日期：2026 年 11 月 4 日。

外部 AEC 查询和当前 Argus 恢复业务都可以改由 BuildX 自有 Revit C# 代码承载。建议按六项原生查询、原生系统图、规则标注的顺序实施，通过功能验收后再移除外部依赖。这里的原生化是让模型业务直接在 BuildX 插件中调用 Revit API；既有 Web 面板和 Codex 连接通过同一个宿主调度这些服务。

当前 AEC 实际提供六项只读查询；`ArgusTools.cs` 实际只包装标注和系统图两项功能。本计划替代这些已调用的能力，不包含原 Argus 产品的全部功能。

## 原生架构与实现边界

```text
BuildX 界面或 Codex 工具
  → 共享命令、权限和回执 owner
  → 既有工作台队列 / ExternalEvent
  → BuildX 原生 C# 服务
      ├─ 文档、视图、元素、参数与几何摘要查询
      ├─ 系统连接图、布局与详图输出
      └─ 标签创建、位置与引线排布
  → Revit API
```

先在同一插件内按职责拆分服务，复用 `WorkbenchHost`、文档身份校验、事务、取消和回执机制。Revit 对象只在有效 API 上下文中读取或修改；可以脱离 Revit 的布局算法处理普通数据，不把活的 Document、Element 或 Connector 对象交给后台线程。ExternalEvent 会在 Revit 可处理时执行，原生化不能消除宿主忙碌造成的等待。[Autodesk External Events](https://help.autodesk.com/cloudhelp/2023/KOR/Revit-API/files/Revit_API_Developers_Guide/Advanced_Topics/Revit_API_Revit_API_Developers_Guide_Advanced_Topics_External_Events_html.html)。

原生代码依据公开 API 和 BuildX 自有数据契约实现。研究程序集及其恢复源码保留在私有研究归档，业务实现不从该程序集反射调用，也不复制恢复算法进入正式源码。

## 六项 AEC 查询迁入 C#

现有清单见 `lib/aec-model-adapter.mjs:19` 和 `lib/aec-read-contracts.json`。契约快照只有输入定义和描述，没有 outputSchema；迁移时必须检查现有消费者，建立 BuildX 自有结果契约，不能声称已知旧输出的所有字段。

| 当前工具 | 原生实现规划 | 现成基础与需要补充的部分 |
| --- | --- | --- |
| `revit_health` | 报告当前宿主、连接与文档状态，区分无文档、忙碌和无法核实 | 复用 `revit_workbench_status` 的生产事实；服务就绪与宿主响应分开表达 |
| `revit_get_document_info` | 当前文档基本信息、项目或族文档类型、活动视图、可观察身份 | 复用宿主文档事实，补明确 DTO；不暴露环境快照或账号信息 |
| `revit_list_views` | 用 Revit 原生收集器列出视图，保留 ID、名称、视图类型及模板事实 | 新增原生读取；定义排序和分页，不把没有检查到的视图说成不存在 |
| `revit_get_element_parameters` | 用现有参数描述能力返回参数身份、存储类型、原始值、显示值、单位和可写性 | 复用 `WorkbenchActions.describe_parameters` 及参数解析 owner |
| `revit_get_elements_by_type` | 按类型、类别、楼层及所选字段过滤，稳定排序后分页 | 扩展现有元素查询；保留调用方 filters 和 fields，类别和楼层由稳定 ID 解析，不按本地化显示名猜测 |
| `revit_get_element_geometry` | 返回位置点或曲线端点、包围盒、楼层与可取得的长度面积体积 | 新增原生几何摘要；首版不需要三角网格、布尔运算或几何引擎 |

主要兼容问题有三类：旧工具描述接受 `Walls`、`Doors` 等类别名，而当前自有查询只认 `OST_*`；旧查询包含类型、楼层和字段选择，现有 search 并非完全等价；旧几何工具描述是摘要，不代表完整曲面或网格。迁移不能直接把工具名改指现有方法后宣布完成。

原生查询统一以下语义：

- 用宿主会话、文档身份和原请求 ID 绑定结果；项目切换、宿主重启或迟到结果不能进入新会话。
- 保留参数原始值和显示值的区别。长度、面积和体积显式带单位；转换集中在数据生产边界，使用 Revit 的单位 API。[Autodesk Units](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Introduction/Application_and_Document/Revit_API_Revit_API_Developers_Guide_Introduction_Application_and_Document_Units_html.html)。
- ElementId 沿用已验证的表示和转换规则；超过 JSON 安全整数范围时不得四舍五入。若需要扩展字符串 ID，须同时更新命名契约和全部消费者。
- 几何数据说明模型坐标系、包围盒变换与缺失原因；无位置、无包围盒、无适用参数均保留显式未知或不适用，不能填零。
- 类别、参数、类型和楼层的 ID 与名称分开。重名、未找到和多候选返回具体原因，不能任意选一个。
- 定义原生结果 schema、实际分页覆盖、截断或预算停止原因；验证发布给工具客户端的 schema 和宿主返回值。
- 在构造集合和序列化前检查扫描、时间与响应预算；分页大小不能代替内存边界。增加宿主能力版本，旧 DLL 明确返回未支持，不自动退回 AEC 链路。
- 一次宿主处理内产生所需文档事实与结果。合并重复状态检查前核对原身份保证，性能收益以等价任务测量为准。

建议新增独立的原生只读服务文件，复用现有参数和元素事实生产者，避免在多个查询中各写一套单位和身份解释。保留有用的公共工具名称；字段、单位或默认行为变化按版本迁移，删除过渡代码前核实全部消费者。

## 系统图优先复用现有原生代码

当前可复用的代码为 `SchematicModel.cs`、`SchematicRevitService.cs`、`SchematicEditorWindow.cs`、`SchematicWindowEntry.cs` 和 `lib/native-schematic-tools.mjs`。源码包含物理连接读取、BFS 基础布局、可编辑 DTO、矩形符号、文字及原生详图线输出；路径不调用 `ArgusLearning.Core.dll`。

这些是可复用源码，尚不能作为产品界面已交付的证明。`LocalCodexRevit.cs:72-73` 当前明确没有在产品 Ribbon 暴露未完成编辑器。源码和既有发布边界文档将其声明为自研，正式建库时仍保留实现来源记录。

首版系统图流程规划为：选择管道或风管网络起点，读取真实物理连接，生成预览，允许调整符号和布局，再按现有权限策略导出原生详图视图。返回真实生成的视图与元素身份，不保存工程，也不把连接图当作水力或风量计算结果。

需要完善的部分：

1. 环路、分支、断连、跨楼层及混合连接器的覆盖说明；基础符号和图例由 BuildX 自有资源提供。
2. 当前 300 节点、800 边及连接器预算属于现有实现限制；首版沿用并实测，超限明确失败或返回有覆盖说明的结果，不静默截断。
3. 文档持久身份与内容新鲜度分开。当前 `documentFingerprint` 实际来自 `ProjectInformation.UniqueId`，不能表示内容版本；导出前除拓扑外，还需核对本次布局所依赖的元素、标签参数和其他源事实。
4. 重复导出策略必须明确。当前实现每次新建视图，不能称为幂等；按原请求核对结果，未知结果禁止自动重放。用户明确要求再次创建时可生成新的视图。
5. 处理取消、回滚、视图创建失败、重连后原回执核对及用户编辑过期预览。回滚生成的临时元素 ID 不代表模型中存在该元素。

迁移完成后，产品使用原生 preview/export 工作流，退出旧恢复版 `revit_build_schematic` 分派。若输入和行为不同，显式迁移命令与界面，不用透明别名掩盖差异。

## 智能标注改为 BuildX 规则排布

标注需要新增自有布局逻辑，但创建标签、调整头部位置和引线可以直接使用 Revit API。`IndependentTag.Create`、`TagHeadPosition` 和 `SetLeaderElbow` 是官方支持的基础；标签文字来自标签族定义的参数，不能把替换标签文字当成普通文本赋值。[Autodesk Tags](https://help.autodesk.com/cloudhelp/2024/ENU/Revit-API/files/Revit_API_Developers_Guide/Revit_Geometric_Elements/Annotation_Elements/Revit_API_Revit_API_Developers_Guide_Revit_Geometric_Elements_Annotation_Elements_Tags_html.html)。

首版建议先覆盖经过验证的二维平面、剖面或立面中的常用管道及阀门类别，逐项支持兼容标签族。一次批次按同类元素和明确标签类型处理；缺标签族、视图不适用、元素不可见或引用不支持时返回具体原因，不自动改模型参数或加载未知资源。

拟定流程：

1. 读取视图方向和比例、元素投影、已有标签、用户选定标签类型及可观察障碍物，生成同一来源的布局输入。
2. 计算锚点、候选方向、标签间距和引线，按重叠、越界与引线交叉等规则排序；先支持确定性布局，保留用户调整。
3. 展示候选位置和未解决冲突。纯数据预览中的文字包围盒属于估计；如果以后通过临时事务测量实际标签尺寸，应将该路径明确归为模型写入并要求可靠回滚。
4. 按当前模型权限策略提交：重新核对文档、视图、元素、标签族和布局依据，创建标签并 Regenerate 后验证实际结果；根据明确的冲突处理策略调整、回滚或报告部分问题。
5. 返回每个对象的成功、跳过、失败或结果未知原因及新标签 ID。识别已有标签，明确跳过、保留或调整策略，避免重复创建。

默认同批写入整体提交或回滚；预先跳过的不适用对象在计划中列明。若以后允许部分提交，需单独定义调用方可选策略与逐项最终结果，不能把已回滚对象报告为创建成功。只有能证明属于 BuildX 的输出才可自动更新或移除，标签名称不能证明对象归属。

布局采用图纸尺寸与视图比例计算，单位转换由同一边界负责。首版效果以所选模型验收，不承诺与 Argus 布局或推理效果相同；通过规则与人工调整迭代质量，当前范围不需要 ONNX 模型或专属推理程序。

预览、提交及迟到结果使用现有审批和回执 owner，不能为原生工具另建一套互不知情的写入队列。模型写入权限沿用当前策略，原生化不扩大自动执行范围。

## 依赖移除与打包调整

| 新功能通过验收后 | 需要同步移除或调整 |
| --- | --- |
| 六项原生查询 | `aec-model-adapter.mjs`、`aec-read-relay.py`、外部契约快照及刷新脚本、AEC 环境配置和安装阻塞；先移除调用和静态 imports，保留可用于新语义的回归案例 |
| 原生标注和系统图 | `ArgusTools.cs`、恢复版工具与宿主分派、宿主中的研究程序集 AssemblyResolve 注册与解析、状态探测和支持能力声明、清单中的恢复程序集要求、专属研究构建入口 |
| 专属依赖没有其他消费者 | 研究 DLL、推理 EXE、模型、原族素材及其传递依赖退出产品清单；原件和历史证据留在私有归档 |
| 新产品清单已验证 | 安装器按新清单重建候选和许可公告，重新验证实际动态加载与包内容，不直接改就绪标记 |

去掉 AEC Python 只能消除这条外部 provider 链。当前 Python 还被 `parse-project-document.mjs` 等文档解析链以及 `codex-client-core.mjs:67-70,297` 的 TOML 配置读取使用；`local-runtimes.mjs` 仍解析 Python。彻底去 Python 需要另立任务替换这两条链。`ScriptRunner.cs` 的编译器依赖单独处理：2026-11-05 已有官方 Toolset 固定来源、私有 17 文件布局和七项生产 wrapper/RSP 离线编译证据，见 `SCRIPT-COMPILER-VERIFICATION.zh-CN.md`；这不代表真实用户脚本执行、客户机环境或 Argus 业务替代已验收。

只清理已证明由这些能力专属拥有且不再被引用的依赖。队列、命令、权限配置、用户历史和当前插件输出继续按迁移计划保留。

## 实施阶段与验收

| 顺序 | 交付 | 验收条件 |
| --- | --- | --- |
| 1 六项查询 | 自有输入与结果契约、C# 读取、工具和界面接线 | 无 AEC Python 和 provider 调用；无文档、未保存文档、重名、缺参数、分页、单位、宿主与项目切换均有明确结果 |
| 2 系统图 | 完善现有原生连接图、预览和导出工作流，迁移旧入口 | 实际管道与风管样例的拓扑和生成元素可核对；环路、超限、源事实变化、重复请求、回滚和未知结果受控 |
| 3 标注 | 原生标签创建、规则布局、冲突反馈和重复标签策略 | 在支持视图和标签族上验证创建、位置、引线、已有标签、比例变化、事务失败和取消；记录未解决冲突 |
| 4 去依赖候选 | 移除旧注册与加载链，更新产品和安装清单 | 在没有外部 AEC 工程与研究程序集的隔离环境中构建；在目标 Revit 实际运行所选功能，安装候选内容与源码一致 |

各阶段先验证数据算法和公开工具边界，再做 Revit 2024 API 编译及可丢弃模型上的实机验收。静态无引用与编译通过只能证明对应层面的结果，不能替代实际标签和详图效果检查。记录等价任务的 token、耗时、CPU 和进程族峰值内存，区分冷、热运行；不以删除文件体积推断加速比例。

本次只形成原生替代规划并更新总计划，未实施业务代码、删除依赖、替换插件、重启服务或操作模型。
