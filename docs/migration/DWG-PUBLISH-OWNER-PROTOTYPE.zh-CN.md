# DWG 文件发布 owner 研究原型

该原型与 Revit 无关，不注册产品工具。默认构建不包含；即使打开实验宏，生产入口也固定返回 `not_started`，因为可信请求、原生用户决定和可证明的完整暂存清单尚未接入。测试注入的决定仅在 `BUILDX_TESTS` 下存在，不能代表人工批准。

受控测试流程只接受一个 `drawing.dwg`，捕获并重核暂存及目标目录身份、源文件身份和 SHA-256；确认事实包括目标目录身份、准确目标路径、大小和摘要。先持久写入原 request ID、请求摘要和 `publishing`，再通过 Windows `CREATE_NEW` 发布，禁止覆盖；完成后检查目标文件身份与字节。中断、身份漂移和观察不确定返回 unknown，不自动重跑，保留源和已有输出。进程重启时仅核对指定原回执，已发布记录仍需独立核实，不能直接认定当前文件成功。

实际 Windows NTFS 隔离测试覆盖独占创建、已有文件、源漂移、额外文件、目录替换、目录联接、并发重复、模拟中断与原请求回查；没有测试真实 Revit 或用户目的地。文件 lease 不是外部导出器沙盒：两次目录枚举之间仍可能加入或替换额外文件，也不能证明导出器没有在暂存目录外写入。目录枚举不是持有贯穿整个导出的可信完整清单：受控反例在最后一次枚举后新增一个额外文件，实验路径仍能发布预期文件，证明仅靠枚举无法满足完整清单。日记记录只包含请求摘要及计划事实，不提供跨进程可信请求句柄、原生选择器、有效人工审批或生产级防篡改/持续所有权。所有这些问题解决并验证前，保持入口关闭，不从原型发布用户文件。

补充原生句柄封闭实验：在隔离 NTFS 目录中先持有目录句柄（分别设置共享标志 0、3、7），再并发尝试创建新子文件、创建指向原文件的硬链接和移动目录；还测试同时持有目录句柄与不共享的源文件句柄。实测三个目录共享设置下均可创建新子文件和硬链接，清单发生变化；同时持有不共享的源文件句柄时，原文件重命名被拒绝，但仍可创建额外子文件及硬链接。目录移动结果在并发场景中不稳定，不能推断其一般保证。

该实验说明：目录句柄及文件句柄即使在导出完成后预先持有，也不能独立证明目录清单已封闭。未引入改变系统权限或等待时间的封闭方案；缺可信目录封闭及 manifest owner，生产入口继续固定关闭。
