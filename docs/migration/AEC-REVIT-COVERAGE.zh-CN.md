例如 `revit_export_ifc` 当前仅关联 `revit_preview_ifc_export`，属于面板策略允许的预检行。`revit_edit_family` 只关联 `revit_family_inspect_job`，其在 MCP 目录中可见，候选面板保护策略仍限制对应入口。上述数字只回答是否存在可匹配契约和候选入口，工具语义仍逐行验证。独立泵族是 BuildX 新增能力，候选含该作业，实机待验，未计入 AEC 103 行。

同一工具对上一候选 `0.8.9-confirmed-write.20261114.2` 也完成核查，139 个载荷通过摘要验证。两个版本的 AEC 关联契约、面板策略及直接 MCP 目录命中行数一致。

## 实施顺序

| 阶段 | 优先工作流 | 当前可复用能力与缺口 | 实机验收 |
| --- | --- | --- | --- |
| 1 | 水泵 RFA、读当前机电模型 | 独立水泵 RFA 已纳入现有候选。现有 `revit_list_levels`、`revit_get_element_geometry`、`revit_list_family_types` 及 BuildX 自有 `revit_get_pipe_network` 提供相应查询入口。补齐设备、标高、系统、管径和连接点的可观察证据。 | 从对话确认生成，实际打开 RFA，回读类别、尺寸、类型和进出水连接器。核对当前项目未被改动。 |
| 2 | 载入水泵、放置设备、创建管段与接管 | `revit_create_pipe` 有原生建管源码，当前候选只打包契约，面板写入策略未开放。`revit_place_family_instance` 当前走固定 C# 模板，仅覆盖无宿主的单标高非结构族。迁移具名原生放置，新增经核验族的受控加载及明确连接器之间的连接，推进直管后再扩直风管、电气导管和固定配件。 | 在独立测试模型上依次回读加载的族与类型、放置点及标高、直管系统与管径。接管以实际相连的端口与网络关系为准。核验取消、过期与回执，应用后由用户决定保存项目。 |
| 3 | 建模、图纸及文件导出 | 按现有同名和具名候选的真实使用频次分批启用。先做常用墙、楼板、标高、视图、图纸和标注，再让 DWG、IFC、NWC 从预检走到独立文件交付。图片导出和真实渲染分别验证。 | 用合成或隔离模型核对现有项目的改变和读回，文件按清单、非覆盖发布和格式可打开验收。 |
| 4 | 批量修改与高级操作 | 按筛选批量写参数、项目参数绑定、删除与中心模型均需单独完成影响范围、审批、事务及原回执验证。保存和关闭绑定实际文档。任意反射与脚本逐行记录已具名替代的工作场景和仍缺用例。 | 核对级联、共享身份、权限过期、锁竞争和未知结果。名称存在或可编译不计实机通过。 |

阶段 2 是水泵族之后的第一批模型写入。优先落一个完整用例，将已经验证的独立 RFA 载入测试项目，放置一台泵，为指定进出水端建立可核验的管段和连接。任务可用一张审批卡描述明确变更，最终仍由本地宿主校验项目、族、类型、系统、标高和端口。对保存项目、覆盖已有族或向中心同步等额外效果单独请求授权。

## 重跑与扩展

在源码根目录执行，参数使用可信的解包候选目录。JSON 可重定向到指定的本地报告路径。

```powershell
node --test tools/audit-aec-revit-coverage.test.mjs
node tools/audit-aec-revit-coverage.mjs 'D:\code\BuildX\artifacts\revit-pump-family-candidate-20261115\package-2024'
```

脚本验证 103 行一一对应、候选清单与载荷、候选 DLL 摘要及确认写入编译标记。使用源码和包内实际命令目录与策略模块生成逐行 JSON。包清单记录编译输入摘要，脚本不从 DLL 反推出运行语义。请使用已知来源的候选，脚本会加载包内 JavaScript 目录模块，哈希匹配证明目录与随包清单一致。程序安装目录及未列入清单的文件将被拒绝。
