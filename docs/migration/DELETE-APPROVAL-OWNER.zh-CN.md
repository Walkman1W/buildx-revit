# 删除操作审批 owner：独立准备切片

本切片没有注册删除命令，也不修改现有权限或 Revit 宿主。它提供独立的进程内 owner：只能通过由未来可信传输层注入的 `consumeVerifiedPreview` 消费一次性原回执；要求明确回滚成功、完整且有界的级联 ID/UniqueId 列表、目标身份、宿主会话、原请求 ID 和有效期。owner 对冻结的文档、请求、预览、原生 token 计算 digest；待可信界面调用的决定对象和后续许可均为进程内单次能力，拒绝伪造、过期和不匹配。

受控测试使用模拟传输 verifier，证明本模块的校验和一次性绑定；不证明该 verifier 已存在，也不证明真实 Revit 回滚、级联清单完整、用户决策来自界面或模型可以安全删除。`issueDecision` 必须仅由可信面板的人类决定路径调用；将模块接到普通工具或把客户端自报的确认传入它是不安全的。

后续须实现并验证：原生回滚预览与有效的单次宿主许可；传输层只接受原请求回执并核验回滚、文档身份和完整影响事实；可信审批 UI 展示实际级联后在所有模式强制逐次确认；封闭动态、手动、原始 dispatcher 的绕行；提交时在宿主内重新核对各 ID/UniqueId，`Document.Delete` 返回集合必须与确认集完全相等，否则事务组回滚；超时或清理未知保留原回执，不自动重放。上述闭环完成前不得登记删除能力。

## 未注册的原生回滚预览核心

`DeleteRollbackPreview.Capture` 是内部 C# 方法，尚未连接宿主队列或面板。它对已保存、可修改的项目文档核对路径、标题、图纸 ID 和 UniqueId；完整扫描最多 100,000 个当前元素的 ID/UniqueId 后，在事务组中执行单次 `Document.Delete`，只接受最多 500 个可映射到扫描事实的删除 ID。内部事务提交后必须确认事务组返回并保持 `RolledBack`，再逐项核对文档身份及所有删除元素的原 ID/UniqueId 已恢复，才返回带 120 秒期限的内存事实。删除失败后的回滚无法确认、回滚后身份缺失或变化均抛出 `RollbackUnknownException`，不能产生可批准结果。

这段代码仅通过受控 API peers 与 Revit 2024 引用编译，未在真实 Revit 中运行；类型级、外部服务和事务外副作用没有被证明可回滚。它尚不签发原生单次许可，也没有接入或核验生产队列中的请求 ID、host session、原回执及访问策略；调用参数目前由未来宿主适配器传入，不能作为可信原生回执或直接交给审批 owner。已有 JS owner 仍使用注入的模拟 verifier，不能证明调用者身份。实现实际宿主适配、不可伪造的原队列回执验证、来源会话与目标绑定、逐次用户决定和提交时精确级联复核前，继续保持所有删除及预览能力未注册。
