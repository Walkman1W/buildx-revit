# 删除操作审批 owner：独立准备切片

本切片没有注册删除命令，也不修改现有权限或 Revit 宿主。它提供独立的进程内 owner：只能通过由未来可信传输层注入的 `consumeVerifiedPreview` 消费一次性原回执；要求明确回滚成功、完整且有界的级联 ID/UniqueId 列表、目标身份、宿主会话、原请求 ID 和有效期。owner 对冻结的文档、请求、预览、原生 token 计算 digest；待可信界面调用的决定对象和后续许可均为进程内单次能力，拒绝伪造、过期和不匹配。

受控测试使用模拟传输 verifier，证明本模块的校验和一次性绑定；不证明该 verifier 已存在，也不证明真实 Revit 回滚、级联清单完整、用户决策来自界面或模型可以安全删除。`issueDecision` 必须仅由可信面板的人类决定路径调用；将模块接到普通工具或把客户端自报的确认传入它是不安全的。

后续须实现并验证：原生回滚预览与有效的单次宿主许可；传输层只接受原请求回执并核验回滚、文档身份和完整影响事实；可信审批 UI 展示实际级联后在所有模式强制逐次确认；封闭动态、手动、原始 dispatcher 的绕行；提交时在宿主内重新核对各 ID/UniqueId，`Document.Delete` 返回集合必须与确认集完全相等，否则事务组回滚；超时或清理未知保留原回执，不自动重放。上述闭环完成前不得登记删除能力。

## 未注册的原生回滚预览核心

`DeleteRollbackPreview.Capture` 是内部 C# 方法，尚未连接宿主队列或面板。它对已保存、可修改的项目文档核对路径、标题、图纸 ID 和 UniqueId；完整扫描最多 100,000 个当前元素的 ID/UniqueId 后，在事务组中执行单次 `Document.Delete`，只接受最多 500 个可映射到扫描事实的删除 ID。内部事务提交后必须确认事务组返回并保持 `RolledBack`，再逐项核对文档身份及所有删除元素的原 ID/UniqueId 已恢复，才返回带 120 秒期限的内存事实。删除失败后的回滚无法确认、回滚后身份缺失或变化均抛出 `RollbackUnknownException`，不能产生可批准结果。

这段代码仅通过受控 API peers 与 Revit 2024 引用编译，未在真实 Revit 中运行；类型级、外部服务和事务外副作用没有被证明可回滚。它尚不签发原生单次许可，也没有接入或核验生产队列中的请求 ID、host session、原回执及访问策略；调用参数目前由未来宿主适配器传入，不能作为可信原生回执或直接交给审批 owner。已有 JS owner 仍使用注入的模拟 verifier，不能证明调用者身份。实现实际宿主适配、不可伪造的原队列回执验证、来源会话与目标绑定、逐次用户决定和提交时精确级联复核前，继续保持所有删除及预览能力未注册。

## 原始队列接线核查（未开放预览）

`WorkbenchHost.ProcessOne` 从共享队列文件名取得请求 ID、读取请求体并核对其 `id` 和 `targetSession`；客户端从 `host.json` 读取 session。现有 `captureReadonlyReceiptOwner` 能固定发布前的请求文件身份和摘要、核查目录链、宿主身份及原响应，解决的是原回执归属与恢复问题；它不独立证明这个请求是由可信面板发起的。对具有队列写入能力的本机调用方，隐藏工具名称、请求体中的 ID/session 或从公开状态读取 session 都不能作为内部发起授权。

因此本次没有新增宿主预览 operation、队列调用或连接模拟 verifier。让预览经现有文件队列直接执行 `Document.Delete` 会使普通队列写入者可以触发该回滚操作，不能满足仅可信内部调用的要求。现有类型参数准备流程只读并签发宿主 token，不能直接证明破坏性预览来源；它没有提供本任务所需的独立内部发起信道。

下一步须先确定并验证可信发起者与 Revit 宿主之间的受限信道及授权边界（包括同用户进程和队列写入者的威胁模型），再由宿主基于自己的 claimed 请求、会话及同一有效文档生成事实，并让可信 Node 发布路径在发布前捕获原请求的文件身份与摘要。只有绑定原请求、host session、文档、回滚确认及完整级联后的原回执，才能交给审批 owner；回执丢失或身份不符仍为未知且不重发。完成这条闭环前，内部 C# 预览核心不可被生产队列调用。

## 未注册的宿主内部准入原语

`DeletePreviewAdmission` 借鉴类型参数原生 token：由宿主进程内持有表，要求有效项目文档、图纸 ID/UniqueId、宿主 session、精确请求 UUID 和模式；只接受进程内 `TrustedDecision` 类型，并调用未来的可信决定验证器。签发后使用单调时钟限制 30 秒；匹配失败和首次消费都会销毁 token。签发前和决定验证后均重新核对文档与目标。该对象仅是原语：进程内类型并非用户决定本身，验证器必须核验并消费来自真实可信面板的具体决定。

当前 WebView 设置禁用 WebMessage，尚无已验证的私有面板→宿主决定信道。不能将 API/队列传入的布尔值、host.json、request ID 或自行构造的对象当成人类授权。该准入 token 是 bearer capability：如果通过可被同用户其他进程读取的共享队列传输，持有读取权限的恶意进程可能窃取或抢先使用；本切片不声称抵御同用户恶意进程，也没有对共享队列提供认证。必须先确定可信信道、ACL、令牌保密与进程身份边界，再将该原语与真实原请求回执 owner、预览和用户决定连接，并完成原队列端到端测试。当前没有注册预览或删除命令。
