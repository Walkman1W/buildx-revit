# 类型参数写入逐次确认验证

日期：2026 年 11 月 5 日。新增 `revit_set_type_parameter`，宿主/程序集 **0.8.8 / 0.8.8.0**。本切片完成对话请求、原生影响准备、用户逐次确认、原生写入和原回执核对的源码及隔离验证。手动命令面板暂不执行此工具；真实 Revit、WebView、Codex 对话及模型效果尚未验收。

## 实际实现

输入只接受显式 type/parameter ID、期望原始四项状态、完整排序的直接实例 ID 清单及期望值。参数事实、存储类型、单位、数值和精确 ID 继续由原 owner 解释。只处理已保存当前项目中的真实 ElementType 与其自有参数；不猜名称、不将实例隐式升级成类型。Double 显式使用 internal，Integer 限 Int32，String 原态/期望值各限 8192 字符；缺值、null、空字符串及 HasValue 分开保留。

对话入口先用实际原子 `get_type_parameter_impact` 核查请求守卫，并取得本宿主准备凭证。Node 将观察事实与完整请求绑定为进程内不可由 JSON 构造的对象；模型自报 ack、普通对象、原始 MCP 或手动命令调用不能代替它。准备读取成功后关闭其原回执；超时、错回执或清理未确认则保留原读取 owner，显示写入尚未开始，并按原请求核对，迟到成功不会继续申请或执行写入。

权限 owner 对 automatic、手动审批权限及 rollback 模式都要求本次用户决定。HTTP 仍只接收原五项决定字段，先核对 Origin/CSRF、客户端、对话、连接及当前权限，再产生单次用户决定凭证。用户看到真实文档、类型/参数身份、完整原态、期望值、单位、模式、直接实例数量及清单；最多逐项展示前 50 个并明确总数。零直接实例也必须确认，不代表间接影响为零。审阅缺失、畸形或异步过期时不出现确认按钮。

原生准备记录绑定真实打开文档身份及完整规范化请求，由既有 `SameOpenDocument` owner 核对；不是按路径/标题相同推断。凭证限 120 秒，最多 128 个待消费条目，过期清除，一次消费。Node 可信批准与原生准备是不同边界；发布前消费 Node 批准，Host 消费原生 token 后才传递内部 permit，重放及 scope 变化拒绝。

写入前重新获取类型和参数，核对原态及完整直接实例清单；设置后立即、Regenerate 后和内层 Commit 后再次按 ID 获取并验证归属、存储/数据类型、值和实例清单。可写性只在 Set 前要求。四个阶段共用一次五秒执行时钟，每阶段仍受 20,000 扫描、500 实例及响应预算限制，超限失败，不发布 partial。人工审阅等待不占此执行时钟。无变化也需要批准并走完整验证。

沿用原事务组和回执 owner：rollback 返回已验证的拟写结果并撤销内存修改，commit 仅保留内存修改，不保存模型。业务 DTO 八项字段与原批准逐项核对；不匹配、通用异常或超时保留 unknown，不推断真实模型已经回滚、不自动重发。范围始终为当前文档直接类型引用，间接效果为 `not_assessed`。

host.json 与 Status 都声明独立 `nativeTypeParameterWritesVersion:1` 和 `set_type_parameter`，Node 另要求最低 0.8.8。旧读取、0.8.5 单实例写及 0.8.7 批量实例策略的最低版本不变；两个实例 setter 继续拒绝类型目标。只读 MCP 仍为 23 项，legacy MCP 也不公开本工具。命令目录明确 `manualExecution:false`，引导从对话发起；没有将全局 enabled 关闭而意外切断对话执行。

任意 C#、保存脚本等仍具有各自较宽权限。本切片不是通用沙盒，不能证明所有脚本的类型效果均受本工具限制。
