# BuildX 托管推理商业版首版方案

已选 `A1 B1 C（保留全部现有能力） D1 E1 F1`。国内首发，保留自带 Codex 和 BuildX 托管推理两种模式，首版采用邀请试用。托管模式的目标是用户安装一次并登录 BuildX。本机 Node 和 Codex App Server 调度工具，云端核验账号和额度、调用模型并记账，Revit DLL 执行操作并保存原始回执。

## 双模式与会员权限

| 能力 | 基础账号 | 托管试用和正式会员 |
|---|---|---|
| 本机软件 | 保留现有 BuildX 功能和数据。具名命令照常使用，Revit 读写沿用原有文档、权限和确认流程。 | 同左。会员不改变宿主执行权限。 |
| 自带 Codex | 使用用户自己的 Codex 安装与授权。BuildX 推理账本不扣积分。 | 可切回自带 Codex。仍由用户自己的提供方计费。 |
| BuildX 托管推理 | 未开通时可从推理入口查看试用或会员。 | 首版由管理员发放试用期和测试积分。真实发行后，会员可包含周期额度并支持增购积分。云端逐请求授权和结算。 |
| 特定付费功能 | 只对已明确列出的功能展示会员入口。现有功能默认免费。 | 有效会员可访问已选付费功能。只有触发托管推理时才消耗推理积分。 |

- 账号登录、付费功能、云推理额度和 Revit 操作权限分别校验。面板模式切换需要等当前轮次和回执核对结束，或者明确取消后清理，再重建 Codex 连接。两个模式的进程身份、配置目录和授权上下文分开。历史原回执按原身份查询。
- 首版付费功能清单为空。可作为后续候选的是团队共享命令库、批量质检报告和行业命令包。每项确定后才注册明确的付费功能 ID。功能校验应在可信执行入口，面板只展示可用状态和购买入口。
- 会员提供有效期与功能权益，积分用于托管推理。试点同时要求有效试用与可用额度。正式销售可评估允许基础账号单买积分，以支持偶尔使用云推理的客户。会员到期不应抹去购买记录，赠送额度和付费余额的有效期应独立确定。
- 账本保留供应商原始用量和用户侧扣减。正式计价按供应商、模型和生效价目版本换算，统一整数记账。首版合成测试使用简单整数费率。异常流没有可信终态时保留预占，待对账后结算或释放。

## 工作树基线

- 分支为 `codex/managed-inference-v1`，起点为跨电脑只读候选 `9b6ae25`。该提交包含四项只读配置、回执链和安装候选源码。
- 主工作区未提交改动留在原处。跨电脑候选已有隔离安装和工具握手记录，真实目标机 WebView、云端推理及会员计量需要各自验收。
- 现有安装计划要求客户自备 Codex。商业版把经许可及版本核对的 Codex 和 Node 放入 BuildX 专用程序目录，使用独立配置和数据根。安装清单、升级和回退只管理 BuildX 自己的文件。 [既有安装计划](PLAN.zh-CN.md#revit-安装包方案) · [跨电脑测试记录](STATUS.md#2026-11-07-跨电脑只读测试包)

## 原始方案选项

| 决策 | 选项 | 实施和验收差异 |
|---|---|---|
| A 首发用户与模型 | **A1 中国大陆首发，验证一个可在目标市场商用的供应商。** A2 OpenAI 支持地区首发，使用 OpenAI API。 | 两条都先固定单一模型。A1 要核对 Responses 的多轮工具调用、SSE 事件、上下文续接、取消和用量字段。需要协议适配时由云网关承担，兼容性先单测。A2 需要核实用户和服务的使用范围。 [OpenAI API 支持地区](https://developers.openai.com/api/docs/supported-countries) |
| B 本机推理接法 | **B1 复用本机 Node 做推理转发。** B2 本机 Codex 直连 BuildX 云网关，由固定的本机凭据程序提供短期凭据。 | B1 让 Node 负责续期、会话解绑和请求关联。新增入口只绑定回环，使用每次启动的短期授权。B2 少一次本机转发，需要在选定 Codex 版本上验证凭据命令、长轮次续期、撤销和 Windows 子进程行为。两条都把供应商密钥放在云端。 [Codex provider 配置](https://learn.chatgpt.com/docs/config-file/config-reference) |
| C Revit 功能 | **C1 复用模型概况、当前选择、标高和构件搜索四项只读。** C2 再加模型警告及限定参数查询。C3 再加一项经确认的实例参数修改。 | C1 用标高查询完成首次闭环。C2 适合首批客户明确要做模型质检时选，增加字段、分页和性能验收。C3 需要对测试模型写入的具体授权，以及审批、回滚、提交后断线、原回执和模型核对验收。 |
| D 会员主体 | **D1 邀请制个人账号，独立额度。** D2 企业工作区，管理员邀请成员，团队共享额度。 | D1 复用现有 BuildX 登录入口。D2 增加组织角色、成员撤销、跨组织隔离、共享余额并发和成员用量归属。两条都允许云端停用试用或会员。 |
| E 收费节奏 | **E1 邀请试用，管理员发放期限和额度。** E2 付费试点，经授权后由管理员按订单开通。E3 自助支付与续费。 | E1 就采集真实推理用量和成本。E2 还要有订单、退款处理和人工对账责任人。E3 增加支付回调去重、开通与取消、退款和订阅对账。金额和供应商预算应基于试点任务成本确定。 |
| F 客户包范围 | **F1 Windows x64 和 Revit 2024，一套安装器。** F2 首发再支持一个明确版本的 Revit。 | F1 验证装一次、登录一次、失败回退、升级保留数据和卸载。F2 需要目标版本独立构建和同等实机验收。开发阶段可先使用隔离候选验证推理和宿主。 |

四项只读是第一条验收用例。两种推理模式仍以当前 BuildX 全能力为产品范围，现有个人命令、资料和受控写入需在托管模式单独验收。启用托管推理前应逐项核对会进入模型请求的工具输出，使用允许字段和用户明确选中的材料。

## 首版实施与验收

| 阶段 | 交付 | 通过条件 |
|---|---|---|
| 1 推理兼容 | 固定 Windows Codex App Server、固定模型和受控云网关，复用独立候选验证方式。 | 真实 Codex 完成文本流、模拟具名工具请求、工具结果续接、最终回答和云端记录。测试慢流、取消及可理解的错误。模拟模型与真实供应商结果分开记录。 |
| 2 账号与额度 | BuildX 账户换取范围受限、可撤销的推理授权。云端单独维护会员、请求用量和额度。 | 有效会员可以发起请求。过期、撤销、跨账号及额度耗尽在云端拒绝。并发请求先预占额度，按上游实际用量结算。重复终态去重。缺终态的请求有待对账状态。 |
| 3 真实 Revit | 新模式连接现有 MCP 和本机执行器。将模型可见的文档标识和真实路径分离，由本机核对文档与宿主。 | 「列出当前模型标高和高度」得到与 Revit 一致的结果。能关联对话轮次、Revit 原请求回执和多个推理用量条目。模型未修改。切换文档、取消和断线均有可读结果，未知执行按原 ID 核对。 |
| 4 干净机交付 | 一套安装包管理私有运行时、清单和 BuildX 数据。让 Python 从首版只读路径的启动条件退出。 | 目标机已有 Revit 和所需 WebView2，无预装 Node、Python 或 Codex。装一次包、登录一次 BuildX、重做标高查询。验证版本握手、升级和回退。 |
| 5 邀请试点 | 按所选会员主体邀请用户，展示试用到期和剩余额度。 | 从真实任务记录完成率、推理与 Revit 等待时间、单任务成本、活跃用户使用量及待对账比率。模型供应商请求与云端账本抽样核对。 |

网关按推理请求采集供应商、模型、请求标识、状态和可用的输入、缓存、输出用量。用户按对话或账期看汇总。原始模型、完整本机路径和原始 Revit 回执留本地。首版上传范围限用户发出的提示词与当前查询所需的字段。模型供应商的数据留存按所选服务另行核验。

## 涉及的代码和先后顺序

1. `lib/api-provider-launch.mjs`、`lib/server-api-gateway.mjs` 和各自测试。先验证固定版本与真实模型的协议，再接可信的授权和用量结算。现有回环测试与真实环境保持独立配置。
2. `lib/buildx-auth.mjs`、`lib/panel-accounts.mjs`、`lib/panel-server-core.mjs` 和 `lib/codex-client-core.mjs`。接入托管推理模式，复用原有账号与连接代际校验。账号切换、授权撤销或退出后，旧授权不能再次触发工具。
3. `lib/codex-profile.mjs`、`workbench-mcp.mjs` 和 `lib/workbench-client.mjs`。限定工具目录，绑定本机文档，保留分页、身份复核和回执。批量统计由宿主侧完成。
4. `tools/buildx-installer.mjs`、`tools/buildx-setup.ps1`、`lib/buildx-paths.mjs` 和 `lib/local-runtimes.mjs`。固定私有 Node 和 Codex 路径，补文件清单、第三方公告、探测、安装和升级回退。

首版通过后，按试点数据选择第二阶段的产品价值。模型质检优先补查询和批量报告。重复作业优先补具名命令与团队共享。写入功能单独完成预览、确认、事务和回执验收。收费阶段再接入订单、退款、订阅和对账，正式客户发行按具体授权和验收执行。

## 2026-11-08 首个验证切片

- 本机 Node 回环转发、专用 Codex provider、网关 Responses 流用量采集、会员准入策略及 SQLite 邀请试用账本已实现。账本验证了额度预占、同一响应去重、重开保留和待对账。真实 Linux Codex 0.166.0 在 WSL 隔离网络内执行 stdio MCP 测试工具，将工具结果续回第二个模拟上游请求。两笔用量均结算，测试余额从 100 变为 96。
- Windows 定向回归通过 157 项，两个可选真实 Codex 测试默认跳过。新的真实 Codex 测试在 WSL 单独执行通过，检查工具结果续接、文本增量和两笔 SQLite 结算。该测试要求独立网络命名空间、仅启用回环接口、临时 HOME 和 CODEX_HOME，并用隔离环境显式指定 Linux Codex。
- 国内上游可先验证阿里云百炼 Responses。官方提供 SSE 完成事件、用量和函数工具结果续接。实际 Codex 请求中的工具命名空间、状态续接、模型选择及隐私约束需用具体供应商和接入点核对。 [百炼创建响应](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-responses) · [百炼函数调用](https://help.aliyun.com/zh/model-studio/qwen-function-calling)
- 真实云网关地址、BuildX 登录签发短期授权、面板双模式切换、完整 Revit 能力接线、Windows App Server、干净客户机和真实国内供应商均待验。云端从可信授权解析账号，验证轮次和供应商响应或会话 ID 的归属，并对模型和请求字段设白名单。试用账本只用于单库候选，正式运行前需要巡检进程异常留下的预占并支持人工对账。正式支付和多实例部署单独验收。

## 2026-11-08 短期授权切片

- `lib/managed-inference-grants.mjs` 在签发及网关受理时查询可信云会话和轮次。默认 60 秒，且不超过已核验会话有效期。服务端只存授权摘要，受理一次即消费。固定模型、轮次、账号和会话校验通过后才允许网关进入积分预占。
- Windows 定向回归 160 项通过，两个可选真实 Codex 测试默认跳过。WSL 回环隔离另行通过 1 项真实 Codex 测试。模拟登录身份为每次模型请求签发单次授权，真实 Codex 执行测试 MCP、续接结果并在账本结算两笔用量。
- 会话核验仍由测试注入。下一步接真实 BuildX 云会话核验、轮次归属及面板双模式。现有本机登录标识仅用于本机身份核对。候选的内存授权适用于单实例，正式运行需另验跨实例共享及注销边界。

## 2026-11-08 登录授权交换切片

- `buildx-auth.mjs` 复用既有请求容量、响应限长、超时和取消，通过构造时固定的 HTTPS `POST /v1/managed/grants` 用内部登录凭据交换短授权。请求体只发送轮次标识。面板账号 owner 在调用前后核对同一用户、会话和身份代际。浏览器账号接口不返回授权或登录凭据。
- 合成登录与签发测试覆盖固定路径、授权轮次错配、退出后迟到响应、取消和底层请求容量回收。账号、许可和网关定向测试 102 项通过，真实 Codex 可选项未重跑。
- 默认产品入口没有配置签发服务地址。真实签发路由仍需验证 BuildX 账号和轮次归属，再接入面板模式切换。真实供应商和 Revit 均未联调。

## 2026-11-08 签发路由切片

- `lib/managed-inference-grant-route.mjs` 提供固定的签发路由，接收登录 bearer 和唯一的轮次字段。受信身份 owner 提供云会话与账号。签发时再次核对当前轮次、账号和有效期，授权不能超过登录有效期。路由限制请求大小、并发和等待时间，超时后的迟到核验不会触发签发。
- 本机登录交换通过回环 HTTP 调用签发路由，验证账号变化、错误轮次、非法请求和超时。Windows 定向回归 106 项通过，另有一个旧可选实测默认跳过。WSL 隔离真实 Codex 另行通过流式工具调用与模拟供应商的两笔结算。
- 身份与云轮次的核验仍由测试注入。接入真实核验、托管模式的面板入口、国内供应商及 Revit 验收后，才能启用产品路由。

## 2026-11-08 云端轮次登记切片

- `lib/managed-inference-turns.mjs` 由可信登录凭据开通服务端轮次。每个登录会话同时保留一个轮次，登记不保存登录 bearer。签发和消费授权时通过可信会话服务核验账号和会话。轮次结束或过期后拒绝新授权，已提交的上游请求仍按原账本结算。
- 109 项定向回归通过。受控 HTTP 测试拒绝跨账号、同账号不同会话和伪造轮次，并按服务端轮次记录积分。WSL 隔离真实 Codex 测试经过回环签发 HTTP，验证本机 MCP 续接和两笔模拟供应商用量。
- 后续接入真实会话核验和托管模式的轮次开关入口。面板组合层可先按显式模式构造既有 Codex 接口，复用连接代际、关闭确认和原回执。Revit、国内供应商及发布均待独立验收。

## 2026-11-08 面板托管准入切片

- `panel-server-core.mjs` 在完整模型工作区可注入可信托管准入 owner，绑定当前 BuildX 账号、Codex 连接代际、provider 身份和模型。原自带 Codex 确认与托管授权分开判定。动态执行、许可复核和 Revit 权限沿用原有入口。面板根据服务端托管状态启用发送。
- HTTP 测试验证无登录、无授权、许可失效和轮次启动期间撤权时拒绝发送。旧连接清理未确认时拒绝重连，成功重连后需要核验新代际。105 项 HTTP、DOM 及相关回归通过。
- 本轮使用受控面板账号、Codex 和模型工具。生产启动入口仍使用自带 Codex。下一步将托管 Codex、转发和云轮次的启动与关闭接入可信运行时组合，再验收模式切换、完整工具及数据出境范围。真实 Revit 和国内供应商均未联调。

## 2026-11-08 托管运行时切片

- `managed-codex-runtime.mjs` 为每次托管连接分配独立回环转发和临时 Codex 配置目录。关闭开始时停止转发，进程退出确认后再释放本轮资源。现有 Codex 连接代际与工具核验继续负责并发启动、迟到回调和重连。
- 定向回归 109 项通过，覆盖创建期间关闭、启动失败、转发清理失败及新代际校验。WSL 隔离真实 Codex 完成 MCP 续接、两笔模拟供应商结算和新代际重连。两次首次关闭都超出既有确认窗口，确认重连被阻断，显式重试清理同一进程后才释放。Windows 原生进程的关闭表现需单独测量。
- 生产面板启动入口仍待组装，托管云端配置、真实 BuildX 登录、国内模型、Revit 和安装包均待各自验收。

## 2026-11-08 面板托管轮次切片

- `managed-panel-inference.mjs` 管理面板当前云轮次。普通发送路径在 Codex 提交前开通轮次。每次推理授权由账号 owner 从该轮次所属登录交换，前后核对会话、代际和有效期。结束、取消或断连后禁止继续领授权。云端开通或关闭结果未知时保留原轮次状态，阻止重叠开通。
- 实际面板 HTTP 与受控 Codex、云会话及签发 owner 联调通过。一轮发送的两个授权归于同一云轮次。开通期间停止时只关闭迟到的原轮次，未提交 Codex。140 项定向回归通过，本轮未重复真实 Codex 测试。
- 下一步接入生产服务的可信模式配置、云轮次开关传输和托管 Codex 工厂。受控配置尚未部署。真实 BuildX 云会话、国内模型、Windows Revit 和安装包均待验收。
