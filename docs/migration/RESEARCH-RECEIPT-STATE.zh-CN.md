# 可信请求与回执研究：未接入

本切片只有内存状态机模型和合成测试，不包含 IPC、持久存储、认证或执行器，不能用于授权或防重。测试中的 `authenticated: true` 仅模拟未来认证器的结论；任何客户端提交的同名布尔值均不可信。批量及项目参数生产入口必须继续关闭。

目标协议需由独立的受信任宿主验证：完整请求摘要绑定操作、参数原值、文档身份和宿主会话；审批界面显示并绑定同一摘要；服务端建立调用方身份并限制管道 ACL，评估同一 Windows 用户下其他进程冒充的威胁；确认不能仅依据客户端传来的 PID、标志位、文件名或共享密钥。密钥保护、ACL、进程身份和安装权限边界必须实测，而非由本模型假定。

在执行前，受信任的单一 owner 必须持久化不可复用请求身份和消费状态并校验存储完整性；只有持久化成功才可执行。事务提交与回执持久化之间崩溃会产生 unknown，恢复只查询原请求和宿主证据，不可重新执行。防止日志截断、回滚或删除还需要可信单调状态或等价的受保护存储；单纯 HMAC 无法检测完整历史回退，也无法抵抗同权限进程窃取密钥。重复请求、身份冲突、损坏、权限异常均失败关闭。

本次测试仅覆盖内存模型的超时后 unknown、假设重启后的状态值、篡改字段与终态匹配，不是进程崩溃、文件持久化、真实管道、认证或 Revit 测试。下一步需实现受限 IPC 和受保护持久 owner，并以独立进程验证并发消费、进程终止、磁盘错误、存储回退、伪造调用方、权限变更与原请求回查；解决不了可信来源时不得开放入口。

## 跨重启认领原型

`research-durable-claim.mjs` 在发布前用独占目录认领请求 ID，写入原请求和 SHA-256 摘要并 flush 文件；已有目录或中途留下的空目录均拒绝再次认领。恢复读取原请求，但一律保持 unknown，不含任何发布或重试动作。独立 Node 子进程分别在模拟发布前、发布后终止；重新认领均被拒绝，模拟发布计数没有增加。并发认领、损坏记录及内存终态模型合计 7/7 通过。此为进程被终止的本机文件系统测试，不是断电、系统重启或真实 Revit 测试，目录元数据和写入顺序的断电持久性未验证；记录含敏感请求，生产接入须落实目录 ACL、保留期限与安全存储。摘要可检查意外损坏，但不防同用户篡改或删除。

同等威胁模型下可延续现有 Origin/CSRF 面板决策、进程内 WeakMap 决策、宿主同文档及 120 秒一次性 token；新工具仍须各自绑定完整审批事实、宿主参数和原态，且审批对象不能从客户端字段构造。现有 token 和回执 owner 依赖内存，进程重启后不能重建，文件原型也尚未接入原队列、宿主回执与匹配核验。真实链路需在同一个入口先完成原请求持久认领再发布，并在重启后按原 ID 只读核查；存储缺失、损坏、发布不确定或回执不一致均保持 unknown。防重仅覆盖同一个请求 ID；新的 ID 不能绕过未决操作，需要按文档与操作范围持久阻塞及明确的恢复策略。受控原型不解决这些问题，因此生产入口仍关闭。

## 范围阻塞研究原型

`research-scope-owner.mjs` 在认领请求 ID 前，先独占建立文档和操作范围的目录；缺失或损坏的认领记录维持 unknown 且不解除阻塞。创建新的 owner 实例后，同范围新 ID 被拒绝。解除需要匹配原 ID、原摘要、范围和终态，再经注入的受信任原回执 owner 验证；通过后将范围记录归档，保留请求记录。模拟验证拒绝缺失、错误身份、摘要及认证失败的回执，再允许验证通过后的新 ID；与前述测试共 9/9。

这里的回执验证器为测试替身，尚未连接实际 `workbench-receipt` 或审批界面；文档/操作范围是由调用方传入的研究字符串，尚未绑定真实宿主文档身份，也未处理跨操作互相影响或多范围原子锁定。测试中新 owner 实例模拟重启后读盘，进程终止测试仅覆盖请求 ID 认领而非范围 owner；真实电源故障、目录落盘、原生宿主回执与并发重启均未验。当前不得注册生产入口。

## 实际回执 owner 的接入差异

新增独立子进程建立范围锁后强制终止，后续新进程 owner 从磁盘检查并拒绝同范围不同 ID，测试合计 10/10。现有生产 owner 当前无法直接跨重启复原：`lib/workbench-receipt.mjs` 第 13 行 `captureReadonlyReceiptOwner` 只在原请求 `.tmp` 存在时捕获文件身份、目录链、宿主身份、payload 摘要与 `interpret` 闭包；它们均在进程内。`lib/workbench-client.mjs` 约第 1036–1046 行在发布前建立 owner，其 `interpret` 依赖当前请求参数及操作专属回执校验；`lib/model-permission-owner.mjs` 约第 207–233 行仅将该对象放入内存 entry 并调用 `inspect()`。重启后从普通 JSON 或模型传入的 ID 直接构造 owner 会丢失原文件身份与解释器证明，不应声称等价。

要正式接通，需在发布前由同一受信任 owner 持久记录捕获的原请求文件身份、目录链、宿主身份、请求字节与操作专属校验所需事实；复原时重新核对目录链、原请求身份和摘要及原宿主，再由代码注册的固定操作解释器核实原回执。持久锁的解除只能调用这个恢复 owner 的 `inspect()` 并要求它返回经操作专属校验的终态，不能接收客户端自报状态；失败和缺字段均继续 unknown。现在研究锁只注入测试替身，尚无可证明等价的恢复 owner，因此保持未接入。

## 恢复适配器研究

`research-recovery-adapter.mjs` 在发布前捕获原文件身份、目录链、原请求摘要、宿主及操作版本并 flush 记录；恢复时重查目录链、宿主、原文件身份与摘要，从 outbox 读取回执并使用固定白名单解释器。独立子进程发布后被终止，主进程恢复时对缺失和 ID、摘要、版本、宿主、状态伪造均保留 unknown，正确合成回执可解析，原请求篡改被拒绝；相关合组合计 11/11。提供 `recoveryVerifier` 用于由服务端持有的记录路径读取，忽略调用者提交的回执内容。

固定解释器目前只支持虚构 `research.synthetic.write@1`，用于证明恢复流程，不代表生产操作或真实原生回执已验证；文件链检查和受控测试不证明断电或同用户恶意篡改。范围锁和此适配器仅具备可组合接口，尚未完成真实生产接线与端到端验证，不能开放入口。锁按范围选择和完整业务原态、实际回执解析、存储 ACL 和保留策略仍需接入验证。

## 类型参数原回执研究接入

适配器固定白名单增加 `set_type_parameter@1`，从原请求恢复业务参数并调用既有 `interpretModelWriteReceipt`，由其执行类型参数结果、宿主时序、操作、事务和文档校验；研究副本将该函数导出供适配器调用。范围锁接入恢复验证器，忽略用户所报回执内容并读取原 outbox。子进程持有范围锁、捕获并发布原请求后终止；恢复后新 ID 被阻塞，缺失及类型影响数量伪造的回执不能解除，匹配原请求的合成生产格式回执通过后解除。研究组 12/12；仅为合成宿主文件夹，非真实 Revit 或断电测试。请求篡改拒绝由同组通用恢复测试覆盖。批量和项目参数各自的生产校验、准确冲突范围和生产权限入口仍未接入，生产功能继续关闭。
