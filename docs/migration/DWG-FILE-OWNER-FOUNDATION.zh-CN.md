# 未注册的单文件发布基础

`GuardedSingleArtifactPublisher` 是内部准备组件，不调用 Revit、没有 MCP 或界面入口，不授予文件写入权限，也不是 DWG 导出功能。它只处理一个非空、最大 64 MiB 的本地 NTFS 文件和一个受限制的 `.dwg` 目标文件名。

准备阶段以普通目录句柄记录从卷根到源/目标目录的文件身份，并对无重解析点、单链接源文件进行独占打开和 SHA-256 记录。发布阶段重新逐层持有不允许删除共享的目录句柄并核对记录；独占源文件、重新核对文件 ID、长度及摘要；在持有目标目录句柄时以 Windows `CREATE_NEW` 创建目标，复制后回读长度和 SHA-256。已有目标不覆盖。测试只在本工程独立 artifacts 子目录中执行，不改变 ACL 或系统权限。

这不是隔离工作区或导出沙箱，也不代表多文件导出清单完整。准备计划不是用户授权或不可伪造的审批令牌；组件没有一次性消费机制、原请求回执、取消或恢复协议。发布创建目标之后失败可能留下部分文件，异常只报告目标是否已创建，不能保证中断时持久回执或自动清理。返回后的文件仍可能被有权限的其他进程改动。必须由未来 owner 在固定威胁模型下完成目的地确认、可审核的实际输出清单、每文件句柄/哈希绑定、部分发布恢复及未知原请求核对，才能将其接到导出流程。不能用 Revit 事务回滚描述文件副作用。

本组件只限定 `.dwg` 单文件，不推断 IFC/NWC 导出器是否可用。Revit 多文件命名、引用文件、同一目录的并发添加、Revit 进程意外中断、目录挂载替换、恶意管理员或底层文件系统异常均未完成验收。真实 Revit 导出与用户目的地均未测试。

## 分阶段日志模型（仍未接线）

`lib/dwg-export-journal.mjs` 是无文件 I/O、无 Revit 调用的纯状态模型。它对原请求 ID、宿主会话、文档和视图身份、staging 身份、选择器会话标识、目标目录身份及有界文件名/源身份/大小/SHA 生成摘要；按顺序记录 staged、审批意图、文件开始、已发布、失败或未知。发布中断会进入 `unconfirmed`，不允许重新开始；确认失败时保留目标是否已创建的事实。所有快照都需要将来由可信 owner 先做持久化 compare-and-set，然后才可以发起文件副作用。

该模型的 `approve` 只是模拟事件，不证明用户看过清单，不是可执行授权；目标选择标识和 staging 身份也是待验证的输入。它没有生产存储适配器、进程间原子持久化、可信对话决策、Revit staging/导出、清单完整性证明或原生回执核查；不能直接用于执行或注册工具。现有 `project-files-picker.mjs` 的原生目录选择器可作为未来用户选择来源，但它返回的路径还未与目的地句柄身份或一次性批准绑定。

## 受控持久记录与宿主 staging 原型

在独立测试目录中，Windows 原语可以对已捕获身份的本地 NTFS 日志目录逐层持有句柄，以 `CREATE_NEW` 建立固定请求 ID 与递增版本命名的记录，`Flush(true)` 并重新核对文件身份、字节长度与 SHA-256；下一版本须核验上一版本身份和摘要。相同版本竞争只能有一个创建者；已经出现的部分记录不会被覆盖或自动重发。原语暴露受控读取结果供 Node 原型验证，测试通过单独编译的 helper 进程贯通两层。它仍没有生产服务接线、跨进程受信任的身份锚定或可信持久状态机，不能证明恶意同用户篡改、系统断电后目录元数据持久性或原请求完整恢复。

`UnregisteredDwgStagePrototype` 只作为宿主 API 形状的原型，接收不可由模型参数提供的内部 lease，并为单个可打印视图使用固定 R2018 选项调用 Revit `Document.Export`；无论返回 true、false 或异常，模拟 lease 尝试记录观察到的文件。额外文件不会删除。由于当前没有生产的隔离 lease、句柄锚定的完整枚举或抗并发替换证明，原型对每次结果固定标记 `ManifestComplete=false` 和 `PublicationAuthorized=false`，不能发布。测试 lease 只在本工程测试目录随机建文件夹、使用合成 Revit peer，不能证明真实 Revit staging 安全。

`dwg-destination-selection-prototype.mjs` 使用注入的选择器和目录身份检查器，只返回绑定原请求的短期、单次选择事实；它不接受请求携带的目标路径，不把选择动作当用户发布批准。测试使用假选择器和检查器，生产选择器、目录文件 ID 重查和逐次人类批准尚未接线。只有这些证据、完整实际输出清单、原请求持久回执和安全发布 owner 一起闭合后，才可评估注册导出工具。
