# BuildX 本机安装候选

这是开发和隔离验证候选，不是可销售产品、商业安装包或已验收的 Revit 版本。当前采用用户自带的本地 Codex 登录，不读取、复制或上传其登录文件。不得未经许可将该接入用于付费或托管服务；商业版必须先核验 OpenAI 正式接入资格及运行组件分发权。

当前 Revit 安装、37 项工具及首次 Codex 授权尚未在新客户机完成端到端验收。候选创建器会列出缺项并阻止安装，例如 AEC 契约快照包含开发机路径、AEC Python 提供方及其依赖、Argus 运行组件分发许可，以及脚本编译器路径与打包方式尚未核实。不要将生成目录发给客户使用，也不要把候选误称为完整安装包。

安装器不会下载、安装或升级 Node、Python、Codex、Revit、WebView2，不会复制对话历史、凭据、运行状态或环境变量。候选需要用户提供现有的 Node 24+、Python 3.11+ 和 Codex 程序路径；计划阶段运行它们的 `--version`。Codex 用户自行完成登录。版本、程序存在和产品包文件校验不代表网络、登录、真实模型工具或商业权限已经验证。

开发验证时使用 PowerShell，并将路径改为明确的新目录（`<...>` 表示待填写，不是可直接执行的命令）：

```powershell
node .\tools\buildx-installer.mjs --build-candidate <新组件目录> <已构建插件目录>
node .\tools\buildx-installer.mjs --plan <组件目录> <新安装目录> <Revit-Addins目录> <node.exe路径> <python.exe路径> <codex.exe路径>
```

生成的 `buildx-package.json` 包含已拷贝文件哈希和明确缺项。`--plan` 核对目录、运行程序、Revit 进程及所有已列组件；只有缺项为空、模块和静态资源图闭合，且不存在冲突时，计划才会允许显式执行 `--apply`。即使允许执行，也仅为实验候选；真实启动、浏览器授权、模型执行及设备验收均需单独检查。

安装到新目录时，配置 `buildx-installation.json` 用一个新随机安装标识绑定 node、python、codex 与本机宿主根目录，程序、插件、数据和队列采用同一个安装根。Revit 启动前检查本机服务身份；身份不符或未知时不接管端口。安装器拒绝覆盖既有目录或相同插件 ID 的已有清单。若写入过程中失败，会保留它新建的安装目录作为回退线索，而不会删除既有路径；插件入口是否发布由错误状态明确标示。用户需要检查后自行决定如何处理该残留目录。

已运行 Revit 时安装计划停止，避免切换正在使用的模型或插件。当前开发机的插件、服务及活动锁不由隔离测试触碰。
