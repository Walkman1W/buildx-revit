# 项目资料历史存储接线合同

本文件描述独立模块 `lib/project-history.mjs` 与知识服务的接口；它们尚未接入面板公共路由，也不代表当前面板的资料绑定或历史引用已经跨重启可用。

## 所有权与身份

宿主需先提供明确归属、已存在、用户私有的绝对数据根，并在初始化和恢复时选择同一根。不要将本模块放入当前对话历史目录，不复用或修改其锁。宿主从已验证产品账号获取稳定的 `userId`，传入 `accountId`；临时 session ID、请求参数和浏览器自报账号不可用作授权依据。模块按账号和项目隔离命名空间；它不是授权系统，也不防同一操作系统用户或管理员直接读取、篡改这些本地文件。记录包含原文和目录路径，宿主应按资料敏感程度选择存储和备份策略。

`createProjectHistory({stateDirectory, accountId})` 返回 `{ok,value}` 或 `{ok:false,error}`。`value` 有异步方法：

- `bind({projectId,rootPath})` 追加绑定；`currentBinding()` 返回最新绑定或 `null`。恢复时验证选定目录的文件系统身份；目录消失、更换或重定向会报错，不能自动转到同一路径的新目录。
- `saveVersion({projectId,path,sha256,source,snapshot})` 保存确切版本，`source` 必须是原始 `Buffer` 且 SHA-256 一致，`snapshot` 是仅含有限数值和普通 JSON 值的完整解析结果。内容按账号、项目、相对路径和源哈希定位；已保存的解析结果不同则报冲突，绝不覆盖。
- `readVersion({projectId,path,sha256})` 返回该版本的原始 `Buffer` 与解析快照；找不到或校验失败时明确报错，不返回新版本。解析快照的关联必须由可信解析生产者保证；文件内哈希检测损坏，并不能防同用户有意篡改。
- `cleanup()` 重试本实例未能确认的文件、目录句柄和锁清理。其他进程正在使用或崩溃后留下的锁会导致 `HISTORY_LOCKED`；模块不会猜测归属或自动删除它们。锁句柄的身份未能取得时会尽力关闭句柄，但保留锁并持续阻塞。清理无法确认时宿主应保留实例、停止后续写入并上报。

默认每账号最多 2000 条、128 MiB；单份原始文件最多 2 MiB，序列化前快照预算默认 12 MiB，并有结构深度与节点数限制。单实例最多允许 4 项进行中或排队操作；超限在复制文件和序列化快照前拒绝。达到预算返回错误，不自动清理旧版本；不支持压缩、删除或淘汰。每次操作读取有界目录清单，规模较大时性能需要实测。

写入先在独立暂存文件完成并同步，再以不覆盖目标的硬链接发布；发布后核对两端身份并删除暂存名称。故障后若留下暂存文件或双链接记录，会阻止后续操作并保留现场，需要有明确授权和可证明归属的人工核查流程；本模块没有自动恢复程序。目标文件系统需支持硬链接。名称检查和删除并非同一原子操作，不能排除同一操作系统用户在检查后恶意替换路径；生产接线需要解决或明确接受这一威胁模型，不能把故障注入通过当成所有权证明。

## 必须的接线顺序

1. 在服务端确认账号和项目身份，确认独立数据根可用；调用及每次异步完成后重新检查当前账号、项目与服务生命周期，防止切换账号期间返回旧资料。退出登录不得把实例转交给另一账号。
2. 用户绑定目录后，先完成原有资料根校验和刷新；保存绑定成功并再次确认账号与目录身份后才采用。恢复时调用 `currentBinding()` 并通过原服务创建与刷新，失败保持未绑定，不能绕过原服务的目录验证。
3. `createProjectKnowledge({projectId,rootPath,history})` 使用宿主可信注入的账号专属 owner。生产者读取原始字节、完成解析后，在发布 indexed 条目前保存同一批原始字节及完整解析快照，失败条目显示 `HISTORY_PERSISTENCE_FAILED` 及具体存储错误；列表的 `persistence` 区分 `durable` 和 `session`。宿主在异步调用后必须复核账号和项目身份。
4. 历史读取必须传入历史中原有的路径和 SHA-256：先调用 `await service.restoreVersion({path,sha256})`，再使用原同步 `read` 或 `table`；项目身份取自 service，成功后沿用相同的分页和结构化计算规则。宿主复核账号和项目身份后才返回结果。不能把 `source` 当成用户指令，也不能以当前文件替换缺失版本。源文件删除后历史快照仍可读取，但当前目录刷新和历史状态应分别展示。当前动态 Agent 桥仍只允许当前版本，历史路由尚未接入。
5. 保持版本格式和解析器语义兼容。未来解析器升级时相同文件摘要可能产生不同快照，当前模块会拒绝覆盖；新增格式版本或显式迁移方案需要先设计，不能静默替换。不可跨版本重新解析原文并声称与当时结果相同。

当前独立测试覆盖新进程恢复、版本损坏、目录替换、账号及项目隔离、额度、未知锁、输入快照变更和并发竞争；经知识服务跨进程恢复修改前文本和已删除 CSV/XLSX 的原始位置与计算，并检查保存失败及重试。没有进行面板路由接线、真实账号、非开发客户环境、异常断电持久性、人工处理遗留锁或完整任务性能测量。进程正常重启与异常崩溃后的自动恢复不是同一保证。操作系统和文件系统的目录项落盘保证也未验证。写入过程或清理失败时可能已有部分或完整记录；应保留并检查确切版本，不能将结果视为肯定未写入。

## 面板接线（2026-10-29）

模型面板可通过进程启动环境中的 `BUILDX_PROJECT_HISTORY_ROOT` 选择已存在、由操作者确认仅当前用户可访问的独立绝对目录；不自动创建该根、不修改 ACL，也不把配置写入机器。目录不得与程序目录或资料目录重叠。未配置时保持会话内索引，界面标注“仅本次会话”；它不应被描述为跨重启已保存。根目录不在此轮已有运行服务上设置，尚未部署到客户安装器。

配置后，以已核验的产品用户 ID 分隔存储；研究模式使用本机研究命名空间。绑定先检查目录身份及与历史根不重叠，再保存绑定并索引；界面可恢复上次项目，也可使用相对路径和 SHA-256 读取历史引用。保存了绑定但索引失败时会明确报告该部分结果。重启后用户需显式点击恢复，当前不自动读取目录。原始字节和解析快照会在该历史目录保存有界副本，请按资料敏感程度管理数据根和备份。

有锁和暂存清理权限的实例会保留确知资源并支持 `cleanup()` 重试；未知归属、进程崩溃留下的锁或暂存不会被自动删除。同一系统用户或管理员能修改该目录，文件系统上路径检查与删除之间不能保证原子身份条件。需要独立目录 ACL、异常断电和真实安装环境验收；本地隔离测试并不证明这些条件。
