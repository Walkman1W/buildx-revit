# 批量参数筛选写入：进程绑定研究与验收边界

状态：研究候选，默认关闭。本文不授权注册或启用 `revit_batch_set_parameters_by_filter`。`6cf45b` 的宏启用路径仍在身份未证明时直接拒绝；现有实验均未连接产品服务或 Revit。

## 已观察到的本地实现

- `revit-addin/LocalCodexRevit.cs` 的 `ServiceStartupProcess` 私有持有 `Process`，`LocalService` 在自行启动子进程时保留该对象，并在宿主关闭时释放。`WorkbenchHost` 目前不能取得该进程句柄。
- `LocalService.EnsureAvailableAsync` 在探测到已有服务时直接复用，因此 `launchedProcess` 可以为空。其 HTTP `service-identity` 响应也未证明响应进程就是新启动的子进程；进程启动后只要探测到匹配响应即可认为服务可用。
- `server.mjs` 承载面板与直接模型调用；Codex 或 MCP 客户端可能是不同进程。由请求体、`host.json`、管道名称或共享路径提供的 PID、令牌和用户决定都不能充当 OS 进程身份或人类审批。
- 安装配置选择现有 `node.exe`，目前没有生产 N-API 文件句柄 owner 的版本、打包和生命周期契约。

## 已完成的独立实验

`9318052ac4e14bb120e7fc9972d36ad21a06cf52` 的 `tools/check-batch-pipe-identity.ps1` 使用本机 Node 22.17.0、Rust 和 C# 假宿主，在独立测试目录运行：

- 现有 Node 管道 PID 实验 6/6；C# 文件 peer 7/7；Node 原生文件 peer 7/7；部分文件失败 1/1；受限管道和模拟回执 15/15。
- 假宿主使用当前用户 SID 的受保护 DACL、`FILE_FLAG_FIRST_PIPE_INSTANCE` 和 `PIPE_REJECT_REMOTE_CLIENTS` 创建管道。回读 DACL 只有当前用户；独立进程提前占名时创建失败。内核返回的管道客户端 PID 与假宿主保活的子进程句柄比较，非目标进程在复制句柄前拒绝。
- Node 测试 addon 直接 `CreateFileW(CREATE_NEW)`，写入并刷新固定合成字节，保持 Win32 文件句柄；假宿主认证进程后 `DuplicateHandle` 并读取该对象。原对象与同内容替换路径的文件 ID 不同；复制句柄共享文件位置。文件 ID、请求 ID、摘要绑定到一次性**内存模拟回执**，重复消费与错误摘要拒绝。
- 测试对照的是受控假宿主，不是 `WorkbenchHost.ProcessOne`、真实队列、生产原回执或真实人类确认。实验 addon 只接受固定合成内容，返回裸 HANDLE，缺少产品所需的安全参数、资源和生命周期封装。失败部分文件测试未把任何请求投递到队列。

本机无法模拟另一用户或远程客户端，故只验证 DACL 内容和拒绝远程标志被指定，**未实测异用户或远程拒绝**。默认实验不抵御同用户进程注入、进程句柄滥用或管理员控制。未验证真实 Revit、模态对话的可见性、取消、模型事务或生产验收。

## 最小接入条件

1. **进程和服务归属。** LocalService 增加内部生命周期 owner，只能向宿主提供它亲自启动并保活的准确子进程句柄。宿主创建管道、显式限制 DACL、拒绝远程并使用首实例；由 OS 获取连接端 PID，与该活进程句柄核对，退出或替换即撤销候选。附着现有服务、无句柄及身份不明一律不可用。握手与回调不得信任 JSON 自报 PID。HTTP 探测只用于界面可用性，不能成为写授权；若面板对审批或请求有权威作用，还须证明响应的监听端属于同一进程，并解决查询和重启竞态。单次 HTTP 响应或 installationId 不足以证明归属。
2. **文件对象和请求。** Node 侧由可信 native owner 以 `CREATE_NEW` 创建、写入、刷新并持有请求文件句柄；认证连接后宿主从受认证进程复制同一个文件对象句柄。宿主从句柄有界读取并冻结字节，绑定唯一请求 ID、摘要、文件身份、会话、活动文档和访问策略。持有句柄不等于文件内容永远不可变；需要定义可写句柄何时失效、共享/并发规则及每阶段事实复核。原文件路径被替换不能转为新的请求，不自动重放。部分写入、句柄复制或身份核验失败不执行。
3. **二进制与运行时。** 实验以本机 `rust-lld`、Node 22.17.0 缓存 `node.lib` 和 N-API 构建；这不是生产交付。产品需固定 Windows x64 N-API 兼容范围、构建与来源清单、完整性哈希、运行时架构和 N-API 校验，以及 HANDLE 所有权、异常、释放和崩溃清理。二进制缺失、版本不支持、哈希或加载失败必须停用候选，不降级为普通文件或自报 JSON。不能安装或改变系统运行时作为隐式修复。
4. **人工确认与 Revit 线程。** 只有宿主原生界面收集明确的人类决定；受控预览必须完整显示条件、目标值和每一项旧值/单位，不能在界面截断时继续。Revit API 和事务只在 ExternalEvent 的 UI/API 线程运行；管道后台线程只维护线程安全的取消、进程存活和断线状态，不访问 Document。模态对话时取消可能只能在其返回后被处理，必须在首次设置及每个设置、再生、提交/回滚阶段前重新核对状态、权限、文档、完整影响集和原态。
5. **原回执与终态。** 由宿主同一原请求产生唯一可核查回执，绑定该次真实结果和事务组状态。Node 在发布前捕获原请求 owner；取消、对话拒绝、权限撤销、目标漂移、提交、完整回滚与未知必须分别表达。超时、断线、回滚失败或回读不明、投递结果不明保持 unknown；只能检查原回执，绝不自动重发。关闭时阻止新请求并按实际生命周期释放管道、句柄和回调；不能把等待结束当作 Revit 已停止。

## 后续验收顺序

1. 抽取可重用生产身份/句柄 owner，保持编译时默认关闭；先用独立假宿主与真实 Node transport 在同一临时队列端到端测试，不连接 Revit。覆盖提前占名、其他 PID、未持有/退出进程、附着服务、原文件同内容替换、目录重解析、摘要漂移、部分文件、重复 ID、失败清理与原回执未知不重发。以可控子进程核查进程和句柄真正释放。
2. 分别对权限撤销、取消和断线与受控 C# 事务 peer 联测，覆盖逐阶段目标漂移、回滚异常/状态不明、结果与回执丢失、每次只发布一个原请求；加入未声明能力、addon 不可用与版本不兼容的拒绝测试。确认既有 read、write 和事件宿主未因默认关闭候选改变。
3. 仅在有受控异用户、远程客户端环境时测试 DACL 和拒绝远程的实际效果；记录进程注入和高权限边界。测试独立客户机上安装包二进制、N-API 版本和升级/关闭行为。
4. 产品路径在完成真实 Revit 原生 UI 可见性、取消和事务验收前保持关闭。任何真实模型或服务变更需覆盖该具体操作的授权；不以模拟或 API 引用编译代替现场验收。
