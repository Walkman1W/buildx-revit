# 资料库地址存储（隔离候选）

`createProjectFilesStore({stateDirectory, accountId})` 接受已存在的本地应用状态目录绝对路径和已核验的稳定账号标识。它只保存显式添加的 `{path, kind}`；当前 Revit 项目的自动目录不写入，文件本身不读取、不复制、不改写。

`ready()` 取得账号目录专属锁、核对完整账本；`list()` 返回地址；`add({path, kind})` 验证所选普通文件或目录后追加，`remove({path, kind})` 即使文件已不存在仍能移除地址；`close()` 核验后释放本 owner 的锁。调用方必须先 `ready()`，成功保存后才应向用户报告重启可恢复。不同账号使用不同的哈希目录；锁冲突、损坏、记录异常、目录身份变化及未知写入均阻止后续修改。Windows 下完整且可识别的旧锁，仅在持有原文件独占句柄、核对文件原字节和全部祖先身份后原样归档，然后竞争新锁。异常账本不会被清理、覆盖或自动重发。

## 不可省略的接入前提

- 接入方提供与现有本地聊天存储相同的状态根；本模块核查目录及祖先身份、拒绝链接并使用独占锁，但不修改、也不证明 Windows ACL。2026-11-01 的只读检查发现当前 `runtime-history` 存在其他主体的继承修改权限，不应宣称该目录仅当前用户可访问。
- 账号与当前连接/界面会话由宿主核验；本模块的账号散列仅作数据分区，并非登录认证或加密。宿主必须把一个操作的选定地址、保存与 UI 状态连起来，处理账号切换、错误及用户撤销。
- 每次写入使用独占文件创建与同步，并顺序校验哈希链；当前进程内能检测外部删改和不同 owner 竞争。锁格式残缺、无法取得独占句柄或辅助程序不可用时仍然阻断并保留原件；异常写入在恢复后仅重读原账本，损坏时不会覆盖或重发。进程重启前的整段记录被他人重写或删除，以及操作系统崩溃/断电时的目录项持久性，不能仅靠本模块证明。
- 固定上限为 64 个地址、4096 条追加事件。达到上限会拒绝新变更，不自动压缩或删除记录。父目录及同用户路径替换的竞态不能由 Node 路径快照完全消除。

测试使用临时目录，验证正常关闭后重建、账号隔离、活动锁阻断、进程退出后的 Windows 锁归档、损坏和外部修改；它不是 ACL、真实用户数据或断电恢复的证明。
