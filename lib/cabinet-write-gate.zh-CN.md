# 柜族写入门隔离契约

本模块没有接入面板、原生队列或 Revit，不允许据此启用柜族写入。它将授权后的原请求身份、摘要、原宿主及账号记录为一个待核对作业；在同一已验证锁内写入并回读记录成功后才返回可发布结果。未知结果继续阻断，只有可信回执核验器确认了原请求终态及用户核对后，才写入消解记录。重新创建门时必须先读取完整账本，并重建未消解的阻断。账本损坏、缺失证明、锁失效、写入及清理结果不明都会失败关闭。

接入者必须实现并独立验证以下所有权边界：

1. 可信原生跨进程独占锁负责验证持有与释放；生产的直接命令和聊天动作均须共用同一个门。当前测试锁只是内存夹具。
2. 私有账本需证明其身份、权限、祖先路径、完整性和需要的持久性。`complete: true` 不是普通目录列举成功的同义词；崩溃或断电时不能证实无遗漏时必须失败关闭。当前没有生产私有账本，测试 JSON 文件不是安全账本。
3. 原生队列接入必须持有准备好的请求及其路径链，验证记录中哈希、文件身份、宿主和授权后，再发布**同一个**请求；返回值本身不是可自由复用的全局写入许可。面板重启后需重新认证稳定账号，将旧会话作为证据而非误认新会话。
4. 真实终态和用户核对必须由独立可信 `verifyTerminal` owner 证明；不得用接口调用方传入的 `confirmed` 字段代替认证。本测试中该字段仅控制模拟验证器。
5. 账本同步、目录项和文件系统的进程崩溃、系统崩溃、断电语义需各自验证。当前只测模拟账本和子进程退出后读取阻断，不证明真实进程锁、真实权限、系统崩溃或断电可靠性。

`node --test lib/cabinet-write-gate.test.mjs` 覆盖正常提交、授权拒绝、伪造终态、损坏／不完整库存、写入和清理未知、并发尝试、隔离子进程记录后退出及重启重建。本测试不创建族或文件到用户工作目录，不操作实际 Revit 服务。
