# 本机 MCP 临时配置编辑器

`external-mcp-config.mjs` 是独立的进程内配置编辑器：可添加、列出、修改或移除至多 32 个本机命令配置，并为选择项构造尚未启动的 `external-mcp-owner`。它没有接入面板或用户接口，进程结束即清空，不读写全局 Codex 配置、不落盘，也不启动服务器。它不是已完成的用户功能。

配置包括名称、绝对可执行文件路径、绝对工作目录及按顺序排列的参数；Windows 当前只接受 `.exe`。参数须显式标记是否敏感，敏感参数在列表及启动提案中显示为 `[REDACTED]`；编辑时可按原索引以 `preserveSensitiveAt` 保留，不需要再次显示值。要更换或移除敏感值需提交新的参数列表。系统不根据字符串推断密钥：用户必须标记敏感参数；名称、路径、未标记参数不得包含已标记的敏感值。环境变量及凭证配置尚不支持。

每次编辑、移除和选择必须携带当前修订号，旧修订不能覆盖新配置。`prepare` 只创建未启动的 owner，后续仍需已实现的独立启动提案和用户确认，也需要真实有效的执行身份保护与回执 owner。调用方必须是可信宿主，不能把 `ownerDependencies` 交给前端或服务器返回的数据，也不能把 owner 本身暴露为任意调用接口。修改、移除配置或关闭编辑器会撤销旧 owner 的后续启动资格：在文件核验、审批、保护器准备各阶段完成后和 transport 启动前均会检查该资格。已经交给保护器启动的操作仍由原 owner 保留，不假定它未发生或自动清理。真实保护器尚未证明启动边界与资格检查原子性，不能将这些内存夹具作为真实进程启动竞争已解决的证明。

创建启动提案时还会检查系统解析后的可执行文件与工作目录路径；如果它们或其他未标记参数包含已标记的敏感值，拒绝提案。Windows 下比较忽略大小写。系统仍无法发现未标记秘密，提案保护不等于已实现凭证管理。

服务器返回的工具名称、描述、Schema，及调用提案中未标记的值、键和敏感路径也会检查已标记的启动敏感值，发现回显则拒绝公开或调用。这个检查不能发现变形、编码或事先未标记的敏感数据。

调用时显式标记的敏感输入同样会与其他参数、嵌套对象键、JSON 指针和随回执公开的工具 Schema 等比较：出现重复即拒绝提案。当前仅支持把非空字符串标记为敏感值；数字、布尔值、null、空字符串、数组及对象须在提案前拒绝，不能假装已完成脱敏。对于获准执行的调用，返回内容仍按显式标记字符串进行遮挡。

如果保护器已返回尚未启动的 transport，但此后资格被撤销或收到关闭请求，原 owner 通过可信保护器的 `disposeUnstarted` 要求明确确认释放；未提供该契约、返回失败或超时时保留资源 owner 并标记 `cleanup_pending`，调用 `close` 可重试，不会新启动服务器。生产保护器尚未实现和证明此契约。

真实启用仍需安全的持久配置位置及权限验证、面板交互、可信进程保护、回执恢复、依赖打包和真实服务器的单独启动授权。这里的修订号只防止同一临时编辑器内的过期更新，不证明文件身份或处理进程崩溃后的恢复。执行 `node --test tests/lib/external-mcp-config.test.mjs` 仅运行内存夹具和对本机 Node 可执行文件的只读启动提案；不启动 MCP 服务器。
