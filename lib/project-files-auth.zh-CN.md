# 资料库地址的 DPAPI 认证候选

`createProjectFilesAuth()` 使用 Windows 当前用户 DPAPI 对精确的记录字节生成或核验认证密文；账号范围参与 DPAPI 的附加熵，范围和字节必须同时匹配。脚本固定，资料地址仅作为数据经标准输入传递，既不作为命令行，也不打开或执行文件。结果不输出密钥；调用方须自行保护和保存完整记录与认证密文。

接口 `seal({scope,payload:Buffer})` 返回 `{ok:true,value:{proof}}`；`verify({scope,payload:Buffer,proof})` 成功时返回 `{ok:true,value:{valid:boolean}}`。DPAPI 校验失败、运行时缺失、结果异常及清理未确认均为失败，不得视作空记录或继续自动授权。`close()` 只管理本 owner 启动的辅助进程；超时后尚未收到退出回执时保留 owner 并拒绝新调用。

## 安全范围和接入前提

- DPAPI CurrentUser 可以让**不同 Windows 用户身份**无法自行构造当前用户的有效记录，前提是辅助进程确实由预期 Windows 用户运行、Windows 系统目录和 PowerShell 可执行程序可信。当前实现未验证辅助程序二进制身份，也未验证 Windows 目录祖先权限或实际对手主体的令牌及组成员；不能据此称整个本地路径或现有 ACL 已获保护。
- 同一 Windows 用户账户下的其他进程可能调用 DPAPI 签发新内容，DPAPI 不是同账号进程之间的授权隔离，也不证明用户按过 UI 按钮。其他系统管理员能力亦未纳入该候选的保障。
- 必须认证完整且规范化的事件字节，包含账户范围、操作、选定路径、类型、序号及上一事件身份；签名与地址添加必须由同一可信宿主关联。未经认证的历史记录不能自动获得读取权限，迁移时应由用户重新确认或保留为不可执行候选。DPAPI 密文不是单独的 ACL 或权限授权。
- 有效旧记录仍可能被回滚、截断或删除；本模块没有独立可信单调锚或可证明的断电持久性。必须将完整性、锁与恢复规则作为独立要求；不能把不存在或缺失记录解释为此前没有操作。
- 每次调用启动一个固定的 Windows PowerShell 进程，性能和部署环境需实际衡量；要求系统 PowerShell 与用户 DPAPI 配置可用。不能用固定真值替代认证失败，也不能因为进程的超时或错误而自动重试任何外部写入。

## 验证

隔离测试在当前 Windows 用户下实际调用 DPAPI Protect 和 Unprotect，精确内容通过、变更内容拒绝、不同范围及修改密文失败；另用假进程覆盖无效输入、未知退出和异常输出。没有模拟不同 Windows 用户登录，也没有验证机器异常断电、真实资料库接入或实际 Revit 会话。
